# 无泄漏滚动评估与概率基线设计

## 背景

项目已有 29 种预测方法，但现有 CLI 回测和测试引擎只切换目标开奖期，没有把该目标期作为预测数据截止点。预测器仍读取完整最新数据，历史回测会包含目标期本身或目标期之后的数据，产生未来数据泄漏。项目中的随机预测仅存在于演示代码，无法作为正式、可复现的比较基线。

本功能新增一个独立的滚动评估器，并提供均匀随机和 Dirichlet 平滑频率两种正式概率基线。评估器直接接收每个目标期之前的历史切片，不复用依赖全局数据管理器的旧预测链路，从结构上保证评估期间无法读取未来数据。

## 目标

1. 对最近若干个可评估开奖期执行滚动样本外评估。
2. 每个目标期只允许使用该期之前、数量受 `periods` 限制的历史数据。
3. 提供 `uniform` 均匀随机基线和 `dirichlet` 平滑经验频率基线。
4. 使用固定随机种子时，同一输入必须产生完全一致的票据和汇总结果。
5. 输出前区平均命中数、后区平均命中数、命中组合分布、全中次数和相对均匀基线差异。
6. 通过根入口 `python main.py evaluate walk-forward ...` 提供文本和 JSON 两种输出。
7. 在 README 中说明算法原理、参数、示例、结果解释和随机性限制。

## 非目标

- 不声称任一算法可以提高真实中奖概率。
- 不把现有 29 种预测器全部迁移到新的数据切片协议。
- 不修改现有 `backtest` 命令或 GUI/API 测试页面。
- 不计算投注收益率、动态奖金或期望收益。
- 不在本任务中迁移共享 `DltRule` 的 2019 九奖级规则。

共享 `DltRule` 仍采用 2019 年九奖级，而最新历史数据已经适用 2026 年七奖级。为避免错误标签，新评估器只报告与规则版本无关的前后区命中组合，不输出奖级名称。

## 架构

### 概率基线

新增 `backend/evaluation/baselines.py`：

- `UniformBaseline` 在前区 1 至 35、后区 1 至 12 中分别执行等概率不放回抽样。
- `DirichletBaseline` 根据训练窗口中的边际出现次数计算平滑权重：

  `p_i = (count_i + alpha) / (draw_count * balls_per_draw + alpha * pool_size)`

- 两种基线都通过注入的 `random.Random` 实例生成票据，不读取全局随机状态。
- 单次生成的多注票据必须合法并去重；候选空间足够时不得静默减少数量。
- `alpha` 必须大于零，训练数据为空、票数非法或号码格式错误时抛出清晰的 `ValueError`。

### 滚动评估器

新增 `backend/evaluation/walk_forward.py`：

- 使用现有 `DltDataSource` 读取并按期号倒序排列公开历史数据。
- 对索引为 `i` 的目标期，训练窗口固定为 `draws[i + 1:i + 1 + periods]`。
- 目标期、更新期以及目标期之后的数据不会进入算法输入。
- 每个“方法 + 目标期”使用由全局种子、方法名和目标期号经 SHA-256 派生的独立种子，确保执行顺序变化不影响结果。
- 每张票记录前区命中数、后区命中数和 `front+back` 命中组合。
- 方法汇总包含评估期数、票据总数、平均命中数、命中组合分布和 `5+2` 全中次数。
- 当同时运行 `uniform` 时，其他方法增加相对均匀基线的前区和后区平均命中差异。
- 结果包含每个目标期实际使用的训练期号范围，便于审计数据截止边界。

### CLI 接入

新增 `backend/evaluation/cli.py` 负责参数校验、调用评估器和格式化输出。根 `main.py` 在导入原有后端主模块之前直接分发 `evaluate` 命令，并更新帮助文本。这样 JSON 模式不会混入旧系统初始化日志，也不需要为两种基线加载深度学习、缓存和硬件检测模块。

命令格式：

```bash
python main.py evaluate walk-forward \
  --methods uniform,dirichlet \
  --draws 30 \
  --periods 500 \
  --count 5 \
  --seed 42 \
  --alpha 1.0
```

参数约束：

- `--methods`：逗号分隔，仅支持 `uniform`、`dirichlet`，默认同时运行。
- `--draws`：正整数，默认 30。
- `--periods`：正整数，默认 500。
- `--count`：每个目标期每种方法的票数，范围 1 至 100，默认 5。
- `--seed`：整数，默认 42。
- `--alpha`：Dirichlet 平滑系数，必须大于零，默认 1.0。
- `--json-output`：仅输出一个可解析的 JSON 对象；常规模式输出紧凑中文摘要。

数据不足、方法名非法、参数越界或历史行格式错误时，CLI 返回非零退出码并输出可操作的错误信息。

## 数据流

1. CLI 解析并校验参数。
2. `DltDataSource` 加载全部历史开奖并倒序排列。
3. 滚动评估器选择最近 `draws` 个具备完整训练窗口的目标期。
4. 对每个目标期构造严格位于其之前的训练切片。
5. 基线算法使用独立派生随机种子生成指定数量票据。
6. 评估器计算每张票的命中数并累计方法汇总。
7. CLI 输出文本摘要或结构化 JSON。

## 测试策略

按照 TDD 顺序实现以下行为：

1. 训练窗口不包含目标期及目标期之后的数据。
2. `uniform` 和 `dirichlet` 生成的票据数量、范围、排序和唯一性合法。
3. 相同种子完全复现，不同种子允许产生不同票据。
4. Dirichlet 平滑权重覆盖未出现号码且总和合法。
5. 命中组合与平均命中数计算正确。
6. 数据不足和参数非法时产生明确错误。
7. 根 CLI 接受新命令，JSON 输出可被 `json.loads` 解析。
8. 运行既有单元测试，确认未影响预测和测试系统。
9. 使用真实 `data/dlt_data_all.csv` 执行至少 10 个目标期、每期 3 注的端到端滚动评估。

## 验收标准

- 自动化测试能直接证明任一目标期的训练最大期号早于目标期。
- 固定参数和种子重复运行的 JSON 结果一致，计时字段除外；正式结果中不包含非确定性计时字段。
- 两种方法均生成合法且数量正确的票据。
- 根 CLI 文本和 JSON 模式均执行成功。
- README 示例命令能够在当前仓库真实运行。
- 全部相关测试通过，差异检查不包含敏感信息或无关文件。
- 真实回测输出明确标注“仅用于历史比较，不代表未来中奖概率”。
